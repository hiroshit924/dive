## 新しいCodex環境での再開

GitHubの取得時に `handoff/2026-11-19` を選ぶ。既存のチェックアウトで別のブランチを開いている場合は、作業ツリーがクリーンであることを確認してから切り替える。

```bash
git status --short --branch
git switch handoff/2026-11-19
git log -1 --oneline
```

`main` のみを取得した環境など、ローカルに作業ブランチがない場合は明示的に取得する。

```bash
git remote set-branches --add origin handoff/2026-11-19
git fetch origin handoff/2026-11-19
git switch --track origin/handoff/2026-11-19
```

Dockerデーモン、Docker Compose v2、Bash、curl、Python 3、tarが必要。JavaScriptの構文確認にはNode.jsを使う。開発用の管理者パスワードは初回だけローカルで入力する。

```bash
read -rs DIVE365_ADMIN_PASSWORD
export DIVE365_ADMIN_PASSWORD
./scripts/start-local.sh
unset DIVE365_ADMIN_PASSWORD
docker compose ps
curl -fsS -o /dev/null http://127.0.0.1:8080/en/
```

既定のポートは `8080`、管理者名は `dive365_local`。他のポートを使う場合は初回起動前に `DIVE365_PORT` を設定する。起動スクリプトはWP-CLIを `raw.githubusercontent.com` から取得し、ComposeはDocker Hubのイメージを使用する。公開コンテンツを取り込む場合は、`dive.c365.jp` へのHTTPSアクセスと、取得データ約600 MBおよびコンテナ側のコピー分の空き容量を用意する。新規の開発用DBで [公開コンテンツの取り込み手順](../README.md#公開コンテンツを開発用サイトに取り込む) を実行する。これで公開コンテンツを再取得できる。現行本番の全データを再現する場合は、本番のDB・アップロードのバックアップを承認済みの保管先から復元する。

新しいDockerボリュームには、元の環境で登録された日程・予約やSMTP設定が含まれない。検証用の日程と予約は新規に作成する。運用データが必要な場合は、承認済みのバックアップから復元する。ステージングと本番の秘密情報は環境設定または承認済みの保管先で扱う。`.env`、SQLダンプ、予約の個人情報、バックアップ一式をコミットしない。Compose内の固定DB文字列はループバックで使う開発専用設定。
